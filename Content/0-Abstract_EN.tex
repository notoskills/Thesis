\Abstract{
Self-sovereign identity is regarded as a viable approach to decentralized health data management. In nearly all published architectures, the required trust anchor is provided by a blockchain; hashgraph-based approaches remain largely unexamined, and the available evaluation results cannot be compared with one another because they rely on differing metrics, load profiles and system boundaries. Whether a pure ordering service without its own state management is suitable as a verifiable data registry at all is therefore an open question.

This thesis answers that question experimentally. Starting from a security-driven reference architecture for the exchange of medical data, its ledger layer based on Hyperledger Indy is replaced by an alternative based on the Hedera Consensus Service, while the agent and communication layers above it remain unchanged. Because Hedera only orders messages and does not interpret their content, state management and authorization checks must be reconstructed above the ledger. This reconstruction is developed across seven documented design decisions, implemented as a proof of concept and measured against the unmodified reference variant in five load scenarios: baseline measurement, load escalation, data growth, node failure and access control.

The core functions of the ledger layer -- registering and resolving identifiers, publishing and retrieving schemas and credential definitions, and revocation -- could be reproduced using the mechanisms of the ordering service and executed in all scenarios. The trust hierarchy, which Indy provides at the protocol level and which would have to be reconstructed above the ledger on HCS, was not implemented; the substitution therefore succeeds for object management, whereas write authorization exists only as a design. Measured performance clearly favors the Indy variant, in latency as well as in saturation behavior, and only on the Indy variant did a node failure resolve without external intervention. The principal contribution of this thesis lies in attributing these disadvantages: the read-latency floor, the collapse under load and the unusable node failure can be traced to the behavior of the client libraries used and are therefore not attributable to the hashgraph consensus mechanism. Statements about a technology and statements about the state of its software must accordingly be read separately.
}
