\Abstract{
Self-sovereign identity is regarded as a viable approach to decentralised health data management. In nearly all published architectures, the required trust anchor is provided by a blockchain; hashgraph-based approaches remain largely unexamined, and the available evaluation results cannot be compared with one another because they rely on differing metrics, load profiles and system boundaries. Whether a pure ordering service without its own state management is suitable as a verifiable data registry at all is therefore an open question.

This thesis answers that question experimentally. Starting from a security-driven reference architecture for the exchange of medical data, its ledger layer based on Hyperledger Indy is replaced by an alternative based on the Hedera Consensus Service, while the agent and communication layers above it remain unchanged. Because Hedera only orders messages and does not interpret their content, state management and authorisation checks must be reconstructed above the ledger. This reconstruction is developed across seven documented design decisions, implemented as a proof of concept and measured against the unmodified reference variant in five load scenarios: baseline measurement, load escalation, data growth, node failure and access control.

The functional substitution succeeds in full: every core function of the ledger layer can be reproduced using the mechanisms of the ordering service, and no scenario fails because the technology lacks a required capability. Measured performance, by contrast, favours the Indy variant clearly, in latency as well as in saturation behaviour and in usable fault tolerance. The principal contribution of this thesis lies in attributing these disadvantages: three of the four main findings can be traced to the source code of the client libraries used and are therefore not attributable to the hashgraph consensus mechanism. Statements about a technology and statements about the state of its software must accordingly be read separately. As a secondary result, four previously unreported limitations of these libraries emerge, revealing a systematic maturity gap between the read and write paths.
}
